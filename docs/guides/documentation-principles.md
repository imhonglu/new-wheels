# 문서 작성 원칙

- Last verified: 2026-08-04
- Verified against: `AGENTS.md`, `CONTRIBUTING.md`, `docs/README.md`, `docs/decisions/README.md`, `docs/plans/README.md`, `docs/decisions/0004-route-documentation-by-reader-and-purpose.md`

이 문서는 형식과 관계없이 문서를 설계하고 유지하는 공통 원칙을 설명합니다. 문서의 위치와 유형은 [저장소 문서](../README.md), TypeScript 소스와 Markdown의 구체적인 작성법은 이 문서의 [문서 유형과 형식별 가이드](#문서-유형과-형식별-가이드)를 따릅니다.

## 독자와 질문부터 정하기

문서를 쓰기 전에 다음을 한 문장으로 정합니다.

- 누가 읽는가?
- 어떤 질문에 답하거나 어떤 작업을 완료하게 하는가?
- 어디까지 설명하고 어디부터 다른 기준 문서로 연결하는가?
- 내용이 맞는지 무엇과 대조할 수 있는가?

독자와 질문이 다른 내용을 한 문서에 계속 추가하지 않습니다. 반대로 같은 독자에게 하나의 작업을 설명하는 내용을 파일 형식이나 구현 디렉터리만을 이유로 나누지 않습니다.

## 사실과 근거

- 버전, 스크립트, 패키지 경계와 CI 단계처럼 바뀔 수 있는 실행 사실은 manifest, 설정, 소스와 워크플로우를 기준으로 확인합니다.
- 문서는 원본을 복제하기보다 사람이 이해해야 할 의미와 판단 기준을 설명하고 원본 경로를 근거로 남깁니다.
- 문서에 현재 수치나 목록을 복사해야 한다면 갱신 조건과 검증 방법도 함께 둡니다.
- 확인한 현재 상태와 앞으로 만들 상태를 섞지 않습니다. 아직 구현하지 않은 내용은 현재 계약처럼 표현하지 않습니다.

근거 파일과 문서가 다르면 어느 한쪽을 조용히 덮어쓰지 않고 구현 결함인지 의도한 정책 변경인지 먼저 판단합니다.

## 단일 소유와 연결

- 같은 사실은 기준 문서 한 곳에서 설명하고 다른 진입점에는 독자가 다음 문서를 선택하는 데 필요한 요약과 링크만 둡니다.
- 링크는 개요에서 상세로 이어지게 하고, 두 문서가 서로에게 설명 책임을 미루는 순환 구조를 만들지 않습니다.
- 공개 패키지의 설치 방법과 대표 예제, 운영 명령 가까이의 안전 경고처럼 즉시 필요한 정보는 링크 뒤에만 숨기지 않습니다.
- 구현을 그대로 읽어 주거나 타입과 설정을 의미 없이 반복하는 설명은 작성하지 않습니다.

## 현재 상태, 결정과 계획

- 현재 시스템 구조와 지속할 기술적 경계·정책은 Architecture에 둡니다.
- 반복 작업에 공통으로 적용할 판단과 수행 기준은 Guide에 둡니다.
- 대안과 트레이드오프가 있는 장기 선택의 이유는 [ADR](../decisions/README.md)에 둡니다.
- 여러 변경에 걸친 미완료 작업은 [활성 Plan](../plans/README.md)에 둡니다.
- 최종 검증 결과와 일회성 구현 과정은 PR이나 커밋 설명에 남깁니다.

현재 문서에 역사 전체를 누적하지 않습니다. 과거 선택의 이유가 앞으로도 필요하면 ADR로 보존하고, 그렇지 않으면 Git 이력을 사용합니다.

## 정보 구조

문서는 가능하면 다음 흐름으로 작성합니다.

1. 결과 또는 문서가 답하는 질문
2. 적용 범위와 전제
3. 필요한 판단 기준 또는 실행 절차
4. 완료 조건과 검증 방법
5. 더 자세한 기준 문서

예제는 핵심 계약을 보여 주는 최소 크기로 유지하고 실제 설정과 명령으로 검증합니다. 예외와 실패 조건은 독자의 다음 행동이 달라질 때 설명합니다.

## 생명주기

- 새 문서는 기존 기준 문서에 같은 책임이 없는지 확인한 뒤 추가합니다.
- 내용이 이동하면 원본과 모든 진입점 링크를 같은 변경에서 갱신합니다.
- 현재 상태 문서가 더는 유효하지 않으면 필요한 내용을 기준 문서에 통합하고 삭제합니다.
- 문서 유형이나 형식별 가이드는 반복되는 고유 책임과 검증 방법이 있을 때만 새로 만듭니다.
