# 문서는 독자와 질문에 따라 연결

- Status: Accepted
- Date: 2026-08-04
- Supersedes: None
- Superseded by: None

## Context

루트 README, 기여 가이드, 에이전트 지침과 `docs/README`가 작업 원칙, 검증 명령과 문서 분류를 각각 반복했습니다. 같은 CI 명령과 동적 기준 숫자를 Markdown에 복사하면 구현이 바뀐 뒤 일부 문서만 갱신될 수 있습니다.

진입점을 하나의 큰 문서로 합치면 중복은 줄지만 사용자, 기여자와 코딩 에이전트가 서로 필요하지 않은 규칙까지 읽어야 합니다.

## Decision

- 루트 README는 프로젝트와 공개 패키지, `CONTRIBUTING.md`는 사람의 기여 흐름, `AGENTS.md`는 코딩 에이전트의 제약과 라우팅을 소유합니다.
- `docs/README.md`는 질문에 맞는 문서 유형과 하위 인덱스로 안내합니다. 공통 원칙은 문서 작성 Guide, 형식별 작성법과 검증은 TypeScript·Markdown Guide가 소유합니다.
- Architecture는 현재 경계, ADR은 선택 이유, Guide는 공통 작업 절차와 작성·검증 기준, Operation은 배포·권한과 실패 복구가 필요한 외부 변경, Plan은 한시적 진행을 소유합니다.
- 같은 사실은 한 기준 위치가 소유하고 다른 진입점은 독자에게 필요한 최소 요약과 링크만 제공합니다.
- manifest, 설정과 테스트 결과처럼 자주 바뀌는 실행 사실은 기계가 읽는 원본이 소유하고 문서는 의미와 탐색 경로를 설명합니다.

## Alternatives considered

### 하나의 유지보수 handbook으로 통합

검색 지점은 하나가 되지만 서로 다른 독자의 진입 정보와 현재 상태, 실행 절차가 다시 한 파일에 섞입니다.

### 각 진입점에 완결된 절차 복사

첫 화면에서 모든 정보를 볼 수 있지만 명령, 버전과 정책을 여러 곳에서 함께 갱신해야 합니다.

## Consequences

- 독자는 자신의 목적에 맞는 진입점에서 기준 문서로 이동합니다.
- 같은 사실의 갱신 지점이 줄지만 일부 세부 절차는 링크를 한 번 더 따라가야 합니다.
- 패키지 README의 설치·대표 예제와 위험한 운영 명령 가까이의 안전 경고처럼 자립성이 중요한 정보는 의도적으로 반복할 수 있습니다.
- 문서 구조 검사는 링크와 형식을 확인하지만 문서 내용의 진실성은 근거 파일과의 검토가 계속 필요합니다.
