# 저장소에는 활성 Plan만 유지

- Status: Accepted
- Date: 2026-08-04
- Supersedes: None
- Superseded by: None

## Context

Plan은 여러 세션에 걸친 작업을 조율하기 위한 임시 문서입니다. 완료된 Plan을 별도 archive에 계속 보관하면 당시 단계와 검증 결과를 쉽게 찾을 수 있지만, 최종 Architecture·ADR·Guide와 같은 내용을 반복하고 오래된 수치와 진행 과정이 현재 문서 검색에 남습니다.

Git 이력만 사용하면 저장소는 단순해지지만, squash되거나 커밋 전에 삭제된 Plan의 내용은 남지 않을 수 있습니다. 따라서 실행 Plan 자체를 영구 기록으로 취급하기보다 완료 전에 지속할 사실과 결정이 기준 문서에 옮겨졌는지를 보장해야 합니다. 활성 Plan만 저장한다면 별도 상태 필드도 새로운 정보를 제공하지 않습니다.

## Decision

- 저장소의 Plan은 현재 작업을 조율하는 임시 문서이며 영구 실행 기록으로 사용하지 않습니다.
- Plan의 존재 자체가 활성 상태를 뜻하며 완료·취소 Plan을 위한 archive와 별도 생명주기 상태를 두지 않습니다.
- Plan을 제거하기 전에 지속할 사실과 결정은 책임에 맞는 현재 문서나 ADR로 옮기고, 구현·검증 이력은 PR과 Git에 남깁니다.

구체적인 작성과 종료 절차는 [실행 계획](../plans/README.md)을 따릅니다.

## Alternatives considered

### 완료된 Plan을 archive에 보관

작업 당시 맥락을 저장소에서 바로 찾을 수 있지만 현재 문서와 결정 기록을 중복하고, 무엇이 여전히 유효한지 독자가 다시 판별해야 합니다.

### Plan을 승격 절차 없이 Git 이력에만 맡김

파일 수는 줄지만 중요한 결정이 커밋 탐색에만 남거나 squash 과정에서 사라질 수 있습니다.

### 완료 상태를 루트 Plan 목록에 유지

상태 전이는 명시적이지만 활성 작업을 찾는 인덱스가 과거 작업 목록으로 커지고 Plan이 영구 문서처럼 사용됩니다.

## Consequences

- `docs/plans`와 인덱스가 현재 진행 중인 작업만 보여줍니다.
- Plan의 상태 필드와 종료 생명주기 검사가 필요 없어집니다.
- 완료 시 지속할 정보를 기준 문서로 옮기는 검토가 필수입니다.
- 세부 실행 과정은 PR과 Git 이력에 의존하며, 기준 문서로 승격하지 않은 일시적 내용은 의도적으로 보존하지 않습니다.
